# Контракт раздачи установщика

Этот документ относится к подготовке выпуска. Автоматическая публикация ещё не подключена; наличие репозитория не является доказательством готовности дистрибутива.

## Границы

- Репозиторий остаётся private до отдельной команды владельца. GitHub Pages не включается автоматически.
- Сюда попадают только материалы страницы, пользовательские документы и разрешённые файлы Releases. Исходники приложения, рабочие базы, внутренние отчёты и секреты не копируются.
- GitHub автоматически создаёт архивы содержимого этого репозитория по тегу. Они не должны содержать исходный код приложения.
- Канал internal остаётся оператору. Первый общий установщик и последующие обновления должны сохранять общий канал на новом ПК.

## Происхождение выпуска

Один проверенный артефакт сборки передаётся на собственный сервер обновлений и в Releases этого репозитория. Повторная ручная сборка под тем же номером не заменяет исходный артефакт. Версия, SHA исходного кода, SHA-256 установщика и сведения о сборке должны сопоставляться однозначно.

Разрешённый комплект включает установщик, контрольные суммы, заметки к выпуску и открытые сведения о подписи/происхождении. Подпись манифеста обновления, Authenticode установщика и TLS-сертификат сервера решают разные задачи и проверяются отдельно. Никаких приватных ключей подписи, SSH-ключей, GitHub PAT, внутренних ключей канала или служебных секретов в файлах раздачи.

Для предварительного alpha-выпуска генератор страницы должен выбрать конкретный проверенный тег и имя артефакта. Нельзя полагаться на GitHub latest, который не принимает prerelease. Старая версия и её файлы сохраняются для диагностики и восстановления; опубликованный файл не подменяется новыми байтами по прежнему адресу.

## Автоматизация

Публикатор должен иметь минимальные права, необходимые для этого репозитория. Учётные данные других проектов не переиспользуются. Изменения workflow и способ авторизации готовятся отдельно; новые постоянные credentials не создаются под видом документационной правки.

Публикация начинается с полного набора файлов и проверок. Видимый выпуск и ссылка скачивания переключаются только после проверки комплектности, хешей и подписей. Повторный запуск должен быть безопасным: тот же артефакт распознаётся, конфликтующие байты не затирают уже опубликованный выпуск.

## Проверка перед открытием доступа

1. Чистая Windows x64 без Python/Node/Git разработчика: установка, первый запуск, реальные зависимости терминала/провайдера.
2. Сведения об издателе и реальное поведение SmartScreen/Smart App Control.
3. Два последовательных обновления общего канала по кнопке с сохранением данных и проверкой восстановления.
4. Отсутствие developer credentials и случайной подписки на internal у получателя.
5. Доступ к обновлению при недоступном GitHub после первоначальной установки.
6. После разрешённого открытия репозитория — анонимное скачивание выбранного установщика и актуальная ссылка на alpha-тег.

Открытие доступа не производится автоматически вслед за merge документации или публикацией файлов в private Releases.
