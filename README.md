**Multi-Agent Trading Platform: collaborative work of specialized AI agents across the trading workflow — from market analysis and trading decisions to execution, position management, and risk control under user governance.**

Golden Breeze is built for collaborative work of specialized AI agents in trading. From a single Control Desk, the user governs agents, their tasks, and access to connected trading accounts: from market analysis, decision-making, position management, and risk control to research, strategy engineering, isolated verification, and the versioned strategy catalog.

## Available in Release v0.21.1-alpha (`stable` channel)

- **Changes in v0.21.1.** v0.21.1 is the first publication of the v0.21 content: the tagged `v0.21.0-alpha` was never published to clients because its build check failed; the update to v0.21.1 is delivered from v0.20.0. New: the strategy "Breakout with multi-timeframe confirmation" now works on the gold symbol of your broker, including names with a broker suffix (for example XAUUSD.a or XAUUSDm), not only on XAUUSD (the timeframe is still M5; earlier versions of the strategy are unchanged); in Studio the list of built-in strategies is visible right after installation, before an account is connected and an instrument is chosen, with the note "Becomes available once an account is connected and an instrument is chosen"; the main agent in chat can read the platform data it needs to write and debug strategies: the strategy catalog (built-in and its own) with limits and check status, the parameters and code of the strategies it wrote, trading agents with their settings and cycle state, agent decisions with errors, and closed trades with results. The agent only reads this data: it does not trade and does not select, apply or launch a strategy or an agent — you still do that in Studio and the Control Desk; what was read is shown under the answer in a "Platform data" card, and the agent shows strategy code only when you ask. Changed: the chat is simplified (the "From Studio" badge, the launch-state icon, the bottom subtask strip, the "Clarify" button with a second field, the "Read-only" label and service progress lines are removed); while the agent answers, an ordinary typing indicator is shown and the send button becomes a "Stop" button in the same place (Enter does not send a new question meanwhile); a request from Studio goes into the input field even when the chat is already open and does not erase what you are typing; the conversation list can be collapsed and expanded at any window width and the choice is remembered; the input field grows with the text; the program name next to the menu collapse button no longer touches it. Fixed: a new agent shows the base strategy right away (it is selected in the draft from creation; nothing is started or enabled); the chat works on any connected core and no longer shows the false "Claude CLI not found" warning when Claude is not installed but another core (for example Antigravity or Codex) is connected and ready, and if no core is connected the chat says so and points to Settings → "Cores"; long thinking modes are no longer cut off at the second minute (the wait for the model answer depends on the thinking level, from two minutes for low to ten for maximum); when an answer fails, the chat shows the concrete reason and, on a timeout, suggests a lower thinking level or a retry. Hosted acceptance of the candidate (clean install and update from v0.20.0-alpha with data preserved) passed; this is a delivery check, not live trading acceptance.
- **Fixes in v0.20.0.** v0.20.0 is a release with no new capabilities for the user; the update to it is delivered from v0.19.2. It fixes the source card under a chat answer that relied on a Knowledge Library document: the card now points at the part of the library document the agent actually read (before, if a search found one part and the agent then read another, the card kept the first); every part that was read is listed with its place in the document, and the parts found by search but not opened by the agent are shown separately under "Found by search, not read". Answers saved earlier are shown as they were stored, under "Sources", with the former place in the document. The release also contains only the server part of a paper-trading simulator (virtual accounts with market and pending orders, SL/TP and a trailing stop, with no access to a live broker); the program has no paper-trading mode yet, so this is not a capability the user can use.
- **Fixes in v0.19.2.** v0.19.2 is a corrective release with no new capabilities; the update to it is delivered from v0.19.1 directly. It fixes: the capability check of an account connected through its own background process now actually reads the account; before, it saved a "broker disconnected" result, so the agent screen reported that account-limit data had not been received while orders on that account were being executed; after an account is reconnected, the Control Desk no longer shows the account-type check taken on the previous connection, and the account label (Demo or Real) no longer lags behind the latest check, while the decisions to start and to send orders still read the account type afresh each time; an order is no longer sent to the broker when, between the first and the repeated risk check, the quote moved so that the loss to the stop plus the commission reserve no longer fits the trade budget (only the agent's trading cycle is affected); in the Control Desk live chart, the "1. Strategy" block shows the calculation of a user-written strategy (a buy signal, a sell signal or no signal, the strategy's explanation and, for a signal, the stop and target) instead of saying there is no strategy data; "Service Checks" answer for the selected agent and its account rather than for the first account in the list or for the previous agent after the selection changes, and permission to execute is granted and revoked for each agent separately.
- **Fixes in v0.19.1.** v0.19.1 fixes: orders from account-bound agents reach the broker again (a repeated risk check before sending wrongly rejected every order of the trading cycle); risk is now recalculated from a fresh quote, and an order that exceeds the risk budget is rejected before it is sent; the execution-diagnostic readiness check no longer refuses falsely on an account connected through its own background process; agents in "broker" mode on such an account pass the fresh account-mode check again ("Prepare launch", start, enabling execution), while a real account on the diagnostic route, a foreign login, or a different server are still rejected.
- **Graphical Control Desk: live MT5 chart, strategy layers & decision breakdown (new in v0.19).** The Control Desk has a live chart: candles come from the MT5 terminal and the last candle moves with the price; zooming and history scrolling are supported, and when several agents are running, the chart, cards, and breakdown of the selected agent come from the terminal of its account. Lines of the applied strategy are drawn over the visible history (for the breakout strategy: the price channel boundaries, the breakout threshold, and the calculation window; the strategy itself computes the values). Candles carry marks for strategy signals, AI core decisions, and broker-confirmed trades; an open position shows entry, stop, and target lines with the trailing-stop steps (`trailing-stop`). The selected decision is broken down along "Strategy → Core → Broker"; a trial decision is labelled "Dry-run entry" without any message that an order was sent. The "Live Quote", "Market & Session Context", and "Event Feed" cards complement the chart: the market context refreshes on its own, while the "One-shot market check (no trades)" remains a separate action (broker schedule, the agent's entry window, channel and ATR, volatility regime, direction across the M5–D1 timeframes, London and New York sessions). The Control Desk layout follows a working session: before launch, preparation and control; while running, the chart takes priority with the selected agent's breakdown, risk, and controls; tiles and the pinned strip open a targeted stop showing the agent name and a masked account number. The chart reads the instruments visible in the terminal's Market Watch and reports when a symbol is hidden. Live acceptance of these scenarios is not published on the showcase.
- **Fixes in v0.18.1.** v0.18.1 fixes: paid FTMO evaluation stages are recognised correctly when the program reads the FTMO account area, and the sign-in window tells a provider error page apart from a network outage; an ordinary Stop requested while an agent is starting is no longer lost and completes only after the agent confirms a clean exit without open positions; provider settings and diagnostics stay available while open positions are being protected; strategy cards show the actual number of passed checks and the exact version name.
- **Parallel trading agents, shared account risk & background MT5 (new in v0.18).** Several trading agents run their own trading cycles in parallel, each with its own account snapshot; agents on the same account share one risk control; each account gets its own background MT5 instance that does not interfere with the user's own MT5 terminal; applying one agent's configuration keeps the other applied agents; and the Control Desk has a pinned panel of running agents. Portfolio and capital management remain planned. After updating to v0.18, versions 0.17.3 and earlier cannot open the updated data: returning requires restoring the backup made before the update.
- **AI core choice in chat, decision memory, ordered Control Desk & FTMO admission (new in v0.17).** The main chat runs on any core connected and enabled in Settings — **Claude CLI**, **Codex CLI**, **Antigravity CLI**, **Kimi CLI**, the **OpenAI**, **Claude**, **Gemini**, and **OpenRouter** APIs, or a local **Ollama** — with a split "Core / Model / Thinking" menu; CLI cores run isolated from the user's own developer instructions, hooks, MCP servers, and tools while keeping the user's sign-in, and API keys are taken from the system credential store. Decision memory has four categories (accepted trades, waiting/HOLD, rejected by risk, core errors) with a bot activity log in Memory and recent events in the Control Desk. Strategies on FTMO accounts no longer need a manual "Behavior Review" step (this is the program's own admission rule, not an approval by FTMO). The Control Desk keeps messages inside the action panel, folds the readiness checklist under "Details (N/N)", connects the MT5 account from Settings on demand when you prepare a launch or run a one-off market review, and moves the emergency core stop into a separate block with two-step confirmation; since v0.17.2, background CLI calls on Windows run without flashing terminal windows. Since v0.17.3, the Control Desk shows the connected account's balance and equity, the "Create API key" button on API provider cards only opens the provider's official key page in the browser (the key is not created or stored automatically), "Refresh models" loads the current model list for API providers and Ollama, and the Claude API works correctly in chat and in the trading cycle.
- **About window and anonymized diagnostic report (since v0.16).** The Control Desk has an "About" window: a build passport (version, short revision with a copy button, channel, build date), application update controls, "What's new" from the bundled changelog for the current version and a downloaded update, and a connectivity check of the server and the memory database. With one button, an anonymized diagnostic report is sent and a `#GB-XXXXXX` reference code is returned — from the About window and from the startup- and update-failure service windows, even when the local server could not start (the code is copied to the clipboard, and the report is saved to a file if there is no connection); personal folder paths, user names, access keys, passwords, and account numbers are hidden automatically.
- **Update, startup, and FTMO sign-in experience (since v0.16).** The update no longer covers the workspace with a white overlay: background download progress is shown in the lower block of the left menu (a dot on the ⓘ button when the menu is collapsed), a compact "Update / Later" reminder appears once per session, and the regular restart on update runs seamlessly without intermediate service windows (the update installation window opens only for locked files, a long check, rollback, or an error); startup and recovery screens follow the light and dark theme. Startup shows a single compact frameless splash screen, and a startup failure opens a full service window. The FTMO sign-in window is a compact single-column 468 px window with a header in the Control Desk palette, a contextual "Back" button on cookie-settings pages, and a curtain during the transition to the cabinet without flashing a service page. The stuck "Reading the cabinet…" status is fixed: a two-phase session check ("Checking the cabinet…" → "Cabinet available" only after the accounts are read successfully) separates an authorization refusal from temporary network failures. Keyboard focus contrast on prop-firm cards and the About button is increased.
- **Strategy catalog and unified Control Desk.** Agent Studio lists implemented trading strategies and registered authored strategies with one recommended version per family, keeps saved configurations without silently swapping the version, and lets you archive and restore authored versions. The Control Desk connects and checks the MT5 account before an agent is activated (balance, equity, broker-confirmed account type, and data freshness) without starting trading, shows a launch-readiness panel where an unknown state is never shown as ready, and separates Stop (no new entries; protection and `trailing-stop` of open positions continue until the broker confirms zero positions), revoking order permission, closing positions, and a permanent emergency core stop; service checks have their own section.
- **Market data, history, and signal check on history — Replay.** A strategy can request up to 500 closed candles of its timeframe and up to three higher timeframes and sees only bars closed at decision time; history completeness, freshness, and session gaps are checked and recorded, and the exact broker symbol is bound to the account and re-checked before execution. Replay runs the same strategy logic window by window on a saved snapshot of real history and counts signals only: **it is not a backtest** and shows no trade execution, profit, equity, or returns. An authored strategy in the new format becomes selectable only after a passed Replay.
- **Trading Agent Control Desk & Agent Studio.** Agent profiles, assignment of trading instrument, account, risk boundaries, and strategy version, strict parameter comparison when applying a Studio draft, immediate market study over closed broker bars even when the market is closed, a **"Market State"** block aligned to the official FTMO schedule, pre-start readiness verification, and desktop window scaling (`25%–500%`) with responsive narrow-window layout (`<= 700px`). Starting and stopping a trading session are distinct explicit user actions; during an active session, the agent manages positions within defined risk limits.
- **Accounts, Prop Firms & MetaTrader 5 (MT5) Trading Integration.** Supports both `Demo` and `Real` accounts via **MT5**, neutral prop-firm and account cards (with GoatFunded explicitly marked as "Support in development"), a unified sign-in window mechanism, **"Connect now"** toggle and automatic adapter selection by platform family (`MT5`/`MT4`), automatic symbol addition to MT5 "Market Watch" and background broker clock verification, dedicated MT5 terminal auto-provisioning with non-activating window placement and automatic termination on disconnect/exit, and verification of account identity/type, auto-trading permissions, and risk boundaries.
- **Agent Chat, Knowledge Library, Strategy Generation & Model Selection.** The "Agent Chat" workspace for trading and research tasks runs the main agent on any connected core (see above), including **Claude CLI** and **Codex CLI (ChatGPT sign-in without an API key)**, with formatted Markdown responses, conversation management and per-chat draft isolation, selection of AI model and reasoning level (`thinking effort`) with requested vs. actual model display, multimodal attachments (`PNG`/`JPG`, text/tables, `PDF`, `DOCX`, and isolated frame extraction from short video clips), a built-in **Knowledge Library** with source/page citations, live **web search**, a **child researcher subagent** in code, and direct in-chat Python strategy generation with isolated synthetic-bar verification and **"Add to catalog"** registration for Agent Studio.
- **`FirstInstall` Installer & Direct Auto-Update (`stable`).** The installer bundles its own Windows x64 runtime and does not require a separate Python installation. Updates are delivered on button click from a dedicated HTTPS update server with **Ed25519** cryptographic manifest signature verification, installed build revision stamp check, child process tree termination (Job Object), preservation of agent profiles and accounts, recovery rollback mechanism, and short anonymized update failure reports.
- **Trilingual Interface (`RU` · `UA` · `EN`).** Switching between Russian, Ukrainian, and English works across the Control Desk, Agent Studio, chat, memory, prop-firm cards, and update notifications, including completed `RU`/`UA`/`EN` localization of the **"FTMO Conditions"** card, **"Terminal Reconciliation"** block, account registration messages, and human-readable readiness statuses in the Control Desk.

## Where We Are Heading (Planned & Deferred)

The strategy catalog, launch-readiness panel, and unified Control Desk, described on November 14, 2026 as main-branch work for the next delivery, are included in the published `v0.15.0-alpha` release and later ones (see above). The graphical Control Desk, listed in the previous snapshot as prepared in the main branch, is included in v0.19 (see above). Next directions (no version number, release date, or completed live acceptance is promised in advance):

- **Planned — Multiple Trading Executors & Portfolio Management:** portfolio coordination of specialized trading agents across instruments and sessions, capital allocation, enforcement of portfolio-wide prop-firm risk rules, end-to-end drawdown control, and market regime analytics. Parallel trading cycles of several agents, shared account risk control, and background MT5 instances per account are included since v0.18 (see above).
- **Planned — Platform Catalog & Dedicated TradeLocker Integration:** expanding the unified registry of prop-firm and platform adapters; in the current release, **MetaTrader 5 (MT5)** is the active trading connector and **FTMO** is the currently supported prop-firm integration, while **TradeLocker** integration is scheduled as a dedicated planned milestone.
- **Planned — Saved Trading Agent Workflows:** repeatable multi-step routines for readiness checks, market study, enforcement of verified prop-firm rules, and scheduled risk control.
- **Design Stage — Licensing & Access Tiers:** architectural design of access keys and closed beta testing modes (`Free` / `Pro` / `Tester`), device binding, and capability tier separation without mixing licensing with trading execution permissions (plans, pricing, and commercial sales terms are not yet approved).
- **Deferred Without Blocking the Current Path:** an expanded Studio with a standalone built-in code editor for manual programming and a custom deep historical backtesting engine with dataset management, as well as purchasing a paid Windows **Authenticode** publisher certificate and a dedicated custom domain (deferred until the product reaches profitability).
