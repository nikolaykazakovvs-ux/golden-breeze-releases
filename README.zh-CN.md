**多智能体交易平台：在用户治理与监管下，专业 AI 智能体跨越完整交易工作流协同作业——从市场分析、交易决策到订单执行、持仓管理及风险控制。**

Golden Breeze 专为交易领域中专业 AI 智能体的协同作业而打造。用户可通过统一的控制台（Control Desk）全面治理各个智能体、分配任务并管理已连接交易账户的访问权限：涵盖从市场分析、决策制定、持仓管理与风险控制，到深度研究、策略工程、隔离验证以及版本化策略目录的完整流程。

## v0.21.1-alpha 发布版可用功能（`stable` 通道）

- **v0.21.1 的变化。**v0.21.1 是 v0.21 内容的首次发布：已打标签的 `v0.21.0-alpha` 因构建检查未通过，从未向用户发布；从 v0.20.0 可更新到 v0.21.1。新增：策略“多时间框架确认突破”现在可在您的经纪商的黄金品种上运行，包括带经纪商后缀的名称（例如 XAUUSD.a 或 XAUUSDm），而不再仅限 XAUUSD（周期仍为 M5；该策略的旧版本保持不变）；在 Studio 中，内置策略列表在安装后立即可见，无需先连接账户和选择品种，并附有提示“连接账户并选择品种后可用”；聊天中的主智能体可以读取编写和调试策略所需的平台数据：策略目录（内置的和它自己编写的）及其限制和检查状态、它所编写策略的参数和代码、交易智能体及其设置和周期状态、带错误的智能体决策，以及已平仓交易及结果。智能体只读取这些数据：它不交易，也不选择、应用或启动策略或智能体——这仍由您在 Studio 和控制台中完成；读取的内容会在回答下方以“平台数据”卡片标明，只有在您要求时智能体才会显示策略代码。变更：聊天已简化（移除“来自 Studio”标记、启动状态图标、底部子任务栏、带第二输入框的“澄清”按钮、“只读”标签以及回答进度的服务行）；智能体回答期间显示常规的输入指示，发送按钮在原位变为“停止”按钮（此时按 Enter 不会发送新问题）；来自 Studio 的请求会进入输入框，即使聊天已经打开，也不会清除您正在输入的文字；对话列表可在任意窗口宽度下折叠和展开，且会记住选择；输入框随文字增高；菜单折叠按钮旁的程序名称不再紧贴该按钮。修复：新智能体立即显示基础策略（从创建起就已在草稿中选定；不会启动或启用任何东西）；聊天可在任意已连接的内核上工作，在未安装 Claude 但另一内核（例如 Antigravity 或 Codex）已连接且就绪时，不再显示错误的“未找到 Claude CLI 程序”警告；若没有连接任何内核，聊天会如实说明并指引到“设置”→“内核”；长时间的思考模式不再在第二分钟被中断（模型回答的等待时间取决于思考级别，从低级的两分钟到最高级的十分钟）；回答失败时，聊天会显示具体原因，超时则建议选择更低的思考级别或重试。已托管运行器上的候选版验收（全新安装，以及从 v0.20.0-alpha 更新且数据保留）已通过；这是分发检查，不是实盘交易验收。
- **v0.20.0 修复。**v0.20.0 是对用户而言不含新功能的版本；从 v0.19.2 可直接更新到该版本。它修复了聊天回答下的来源卡片（回答依据了知识库文档的情况）：卡片现在指向智能体实际读取的那部分知识库文档（此前，若搜索找到某一部分而智能体随后读取了另一部分，卡片仍保留第一部分）；每个已读取的部分都会标明其在文档中的位置，搜索找到但智能体未打开的部分则在“搜索已找到，未读取”标题下单独列出。此前保存的回答按保存时的样子显示，位于“来源”标题下，并保留原来的文档位置。该版本还只包含模拟盘交易模拟器的服务端部分（带有市价单和挂单、止损/止盈与跟踪止损的虚拟账户，无法访问真实经纪商）；程序中尚无模拟盘交易模式，因此用户无法使用该功能。
- **v0.19.2 修复。**v0.19.2 是不含新功能的修复版本；从 v0.19.1 可直接更新到该版本。修复内容：通过独立后台进程连接的账户，其账户能力检查现在会真正读取该账户；此前它会保存“经纪商已断开”的结果，导致智能体界面提示未获取到账户限额数据，而该账户上的订单实际仍在执行；重新连接账户后，控制台不再显示上一次连接时做出的账户类型检查，账户标签（Demo 或 Real）也不再落后于最近一次检查，而启动与发送订单的决策仍每次重新读取账户类型；若在首次与二次风险检查之间报价变动，导致到止损的亏损加上佣金预留已超出该笔交易预算，订单不再发送给经纪商（仅影响智能体的交易循环）；在控制台实时图表中，“1. 策略”区块会显示用户自编策略的计算结果（买入信号、卖出信号或无信号、策略说明，以及信号对应的止损和目标），而不再提示没有策略数据；“服务检查”针对所选智能体及其账户作答，而不再针对列表中的第一个账户，或在切换选择后仍针对原来的智能体，并且执行许可现在按每个智能体分别授予和撤销。
- **v0.19.1 修复。** v0.19.1 修复：绑定账户的智能体订单重新可以送达经纪商（发送前的二次风险检查曾错误拒绝交易循环中的每一笔订单）；风险会按最新报价重新计算，超出风险预算的订单会在发送前被拒绝；执行诊断的就绪检查不再对通过独立后台进程连接的账户误报失败；此类账户上处于“经纪商”模式的智能体重新通过最新的账户模式检查（“准备启动”、启动、启用执行），而诊断路径中的真实账户、他人的登录名或服务器仍会被拒绝。
- **图形化控制台：MT5 实时图表、策略图层与决策解读（v0.19 新增）。** 控制台新增实时图表：K 线来自 MT5 终端，最新一根 K 线随价格移动；支持缩放与历史翻页，多个智能体运行时，所选智能体的图表、卡片与决策解读均取自其账户所在的终端。所应用策略的线条绘制在可见历史上（突破策略为价格通道边界、突破阈值与计算窗口；数值由策略自身计算）。K 线上标注策略信号、AI 内核决策与经纪商确认的成交；已开仓位显示入场线、止损线和目标线，并标出移动止损（`trailing-stop`）的步进。所选决策按“策略 → 内核 → 经纪商”链路逐步解读；试运行决策标为“试探性入场”，不会显示订单已发送的消息。“实时报价”“市场与时段背景”“事件流”卡片与图表配合：市场背景自动刷新，“一次性市场检查（不交易）”仍是单独的操作（经纪商时间表、智能体入场窗口、通道与 ATR、波动率状态、M5–D1 各周期方向、伦敦与纽约时段）。控制台布局围绕工作会话设计：启动前为准备与控制，运行中图表优先，并显示所选智能体的解读、风险与控制；方块与固定条可打开针对性停止，并显示智能体名称与账户号码掩码。图表读取终端“市场报价”窗口中可见的品种，并在品种被隐藏时提示。这些场景的实时验收尚未在展台发布。
- **v0.18.1 修复。** v0.18.1 修复：读取 FTMO 账户区域时可正确识别付费评估阶段，登录窗口可区分提供商错误页面与网络故障；在智能体启动期间提出的普通“停止”请求不再丢失，并且只有在智能体确认已干净退出且无持仓后才会完成；在对未平仓持仓进行保护期间，提供商设置与诊断仍可使用；策略卡片显示实际通过的检查数量和确切的版本名称。
- **并行交易智能体、账户共享风险与后台 MT5（v0.18 新增）。** 多个交易智能体并行运行各自的交易循环，每个智能体都有独立的账户快照；同一账户上的智能体共享同一风险控制；每个账户使用独立的后台 MT5 实例，不会干扰用户自己的 MT5 终端；应用某个智能体的配置时会保留其他已应用的智能体；控制台提供固定显示的运行中智能体面板。投资组合与资金管理仍在规划中。更新到 v0.18 后，0.17.3 及更早版本无法打开已更新的数据：如需回退，必须恢复更新前创建的备份。
- **对话中选择 AI 内核、决策记忆、有序的控制台与 FTMO 准入（v0.17 新增）。** 主对话可在“设置”中已连接并启用的任一内核上运行——**Claude CLI**、**Codex CLI**、**Antigravity CLI**、**Kimi CLI**、**OpenAI**、**Claude**、**Gemini** 与 **OpenRouter** API，或本地 **Ollama**——并采用“内核 / 模型 / 思考”分区菜单；CLI 内核在保留用户登录状态的同时，与用户自己的开发者指令、钩子、MCP 服务器和工具隔离运行，API 密钥在调用时从系统凭据存储中读取。决策记忆分为四类（已接受的交易、等待/HOLD、被风控拒绝、内核错误），“记忆”中提供机器人运行日志，控制台中显示最近事件。FTMO 账户上的策略不再需要手动“行为审查”步骤（这是程序自身的准入规则，并不代表 FTMO 的批准）。控制台将消息显示在操作面板内，将就绪检查清单折叠到“详情 (N/N)”下，在准备启动或进行一次性市场分析时按需连接“设置”中的 MT5 账户，并将内核紧急停止移至带两步确认的独立区块；自 v0.17.2 起，Windows 上的后台 CLI 调用不再闪现终端窗口。自 v0.17.3 起，控制台会显示已连接账户的余额和净值；API 提供商卡片上的“创建 API 密钥”按钮仅在浏览器中打开提供商的官方页面（不会自动创建或保存密钥）；“刷新模型”可获取 API 提供商和 Ollama 的最新模型列表；Claude API 在对话和交易循环中可正常工作。
- **“关于”窗口与匿名化诊断报告（自 v0.16 起）。** 控制台提供“关于”窗口：构建信息（版本、带复制按钮的短修订号、通道、构建日期）、应用更新管理、针对当前版本和已下载更新的“更新内容”（来自随附的更新日志），以及与服务器和记忆数据库的连接检查。一键即可发送匿名化诊断报告并获得 `#GB-XXXXXX` 工单编号——可在“关于”窗口中，也可在启动失败和更新失败的服务窗口中使用，即使本地服务器未能启动也可用（编号会复制到剪贴板，无网络连接时报告会保存为文件）；个人文件夹路径、用户名、访问密钥、密码和账号会被自动隐藏。
- **更新、启动与 FTMO 登录体验（自 v0.16 起）。** 更新不再用白色遮罩覆盖工作区：后台下载进度显示在左侧菜单下方区块（菜单折叠时在 ⓘ 按钮上显示圆点），每个会话仅出现一次紧凑的“更新”/“稍后”提醒，更新时的常规重启无缝完成，不再出现中间服务窗口（更新安装窗口仅在文件被占用、检查耗时较长、回滚或出错时打开）；启动与恢复界面与浅色和深色主题保持同步。启动时显示统一的紧凑无边框启动画面，启动失败时则打开完整的服务窗口。FTMO 登录窗口改为紧凑的 468 px 单列窗口，顶部使用控制台配色，cookie 设置页面提供上下文“返回”按钮，进入 FTMO 门户时使用遮罩过渡，不再闪现服务页面。已修复读取 FTMO 门户时状态卡住的问题：采用两阶段会话确认（先提示正在检查门户，仅在成功读取账户后才提示门户可用），并区分授权被拒与临时网络故障。同时提高了自营公司卡片和“关于”按钮上键盘焦点的对比度。
- **策略目录与统一控制台。** 智能体工作室列出已实现的交易策略和已注册的原创策略，每个系列一个推荐版本，保留已保存的配置而不自动替换版本，并支持原创版本的归档与恢复。控制台在激活智能体之前连接并检查 MT5 账户（余额、净值、经纪商确认的账户类型及数据新鲜度），不会启动交易；提供启动就绪面板，未知状态绝不显示为就绪；并将「停止」（不再开新仓，已开仓位的保护与 `trailing-stop` 持续到经纪商确认持仓为零）、撤销下单许可、平仓以及常驻的内核紧急停止分开；服务检查有独立分区。
- **市场数据、历史与基于历史的信号检查 — Replay。** 策略可请求其时间周期最多 500 根已收盘 K 线以及最多三个更高时间周期，决策时只能看到已收盘的 K 线；历史的完整性、新鲜度及交易时段间缺口会被检查并记录，经纪商的精确品种绑定到账户并在执行前复核。Replay 在已保存的真实历史快照上逐窗口运行同一策略逻辑，只统计信号：**这不是回测**，不显示成交、盈利、净值或收益率。新格式的原创策略只有在 Replay 通过后才可被选择。
- **交易智能体控制台与智能体工作室（Control Desk & Agent Studio）。** 提供智能体配置文件、交易品种分配、账户与风险边界设定、策略版本选择、应用工作室草稿时的严格参数对比、闭市期间仍可基于经纪商已闭合 K 线立即执行的市场分析、遵循 FTMO 官方时间表的**“市场状态”**模块、启动前就绪检查，以及桌面窗口缩放（`25%–500%`）与窄窗口自适应布局（`<= 700px`）。交易时段的启动与停止为明确独立的用户操作；在活跃时段内，智能体严格在设定的风险限额内管理持仓。
- **账户、自营交易公司（Prop Firm）与 MetaTrader 5 (MT5) 交易接入。** 支持通过 **MT5** 连接模拟账户（`Demo`）与实盘账户（`Real`），提供中立的自营公司与账户卡片（GoatFunded 明确标记为“支持开发中”）、统一登录弹窗机制、**“立即连接”**开关与按平台系列（`MT5`/`MT4`）自动匹配适配器、自动将交易品种添加至 MT5“市场报价”并后台验证经纪商时钟、专用 MT5 终端自动初始化配置及不抢占焦点的窗口放置与退出/断开时自动安全关闭，以及验证账户身份/类型、自动交易权限与风险边界约束。
- **智能体对话、知识库、策略生成与模型选择。** 用于交易与研究任务的“智能体对话”（Agent Chat）工作区支持主智能体在任一已连接的内核上运行（见上文），包括 **Claude CLI** 和 **Codex CLI（通过 ChatGPT 登录，无需 API Key）**，并渲染格式化 Markdown 回复，支持对话管理与跨对话草稿隔离、AI 模型与思考深度（`thinking effort`）选择及显示请求模型与实际模型、多模态附件（`PNG`/`JPG`、文本与表格、`PDF`、`DOCX` 及隔离提取短视频帧）、带来源/页码引用的内置**知识库**、实时**网络搜索**、代码中实现的**子研究员智能体**，以及直接在对话中生成 Python 策略代码、基于合成 K 线隔离验证并通过**“添加到目录”**注册至智能体工作室。
- **`FirstInstall` 独立安装程序与直接自动更新（`stable`）。** 安装包内置独立的 Windows x64 运行环境，无需单独安装 Python。只需点击按钮即可从专用 HTTPS 更新服务器获取更新，更新包附带 **Ed25519** 加密清单签名校验、已安装构建版本修订戳检查、子进程树安全终止（Job Object）、保留智能体配置与账户数据、更新故障恢复回退机制，以及更新失败时的简明匿名故障报告。

## 历史快照：0.13–0.14-alpha 周期已交付功能与实时验收状态（v0.14.0-alpha，快照截至 2026 年 11 月 12 日）

本节所述检查属于此前的 `v0.14.0-alpha`（`stable`）安装包，不会沿用到 `v0.21.1-alpha`；功能交付与按环境和账户类型已证实的验证场景分开说明：

1. **知识库、多模态附件、网络搜索与对话中的子研究员智能体：**
   - 支持在对话消息中附加屏幕截图与图表、文本与表格文件、带有文本层的 `PDF`、`DOCX` 以及短视频片段（不超过 10 MB 且时长在 10 分钟以内——在隔离进程中提取视频帧，不进行音频识别）；
   - 主智能体支持通过 **Claude CLI** 和 **Codex CLI（通过 ChatGPT 登录，无需 API Key）** 完整运行，并具备格式化 Markdown 渲染能力（通过 Claude CLI 的主对话实时交互已在 `v0.14.0-alpha` 验收期间在桌面界面中确认）；
   - 内置**知识库**（存储书籍、文档和笔记，支持按来源和页码/章节引文进行检索与阅读）、记录 URL 和访问时间戳的实时**网络搜索**，以及将研究任务委派给**子研究员智能体**（代码中已实现，其访问权限严格受限于知识库和网络搜索，无权访问交易账户；在测试机上对子研究员委派的独立实时验收仍在后续检查计划中）。
2. **对话内策略代码生成、隔离验证与工作室目录注册：**
   - 主智能体可直接在对话中编写和优化 Python 策略代码；应用程序根据语法白名单校验代码，并在内存受限的隔离进程中基于合成 K 线执行验证（旨在验证代码可执行性与核心不变式，而非执行深度历史回测）；
   - 对话回复中渲染策略卡片，提供代码预览及**“添加到目录”**按钮，注册成功后即可在智能体工作室中直接选用该版本，无需手动复制文件。
3. **闭市分析、经纪商时区、控制台与 MT5 终端生命周期管理：**
   - 闭市期间通过**“研究市场”**按钮立即分析已闭合 K 线，无需等待实时 Tick 报价推送；历史数据在常规日内休市和周末休市期间保持持久化；遵循 FTMO 官方交易时间表的**“市场状态”**模块，以及按已验证的服务器时区对周 K 线进行日期对齐（包括夏令时/冬令时转换）；未经确认 UTC 时间戳的 K 线绝不会传入交易管线；
   - 等待历史数据同步期间自动将交易品种添加至 MT5“市场报价”窗口；在连接账户和选择智能体时后台预热验证经纪商服务器时间；在控制台就绪检查中对等待原因给出明确说明；
   - 添加账户时提供**“立即连接”**开关并根据平台系列（`MT5`/`MT4`）自动匹配适配器；专用 MT5 终端自动初始化配置（在终端设置中自动启用算法交易权限并预置标准工作区）、采用不激活焦点的窗口放置方式，并在退出程序或断开账户连接时自动安全终止；校验已安装构建版本的修订版标识戳；完成**“FTMO 交易条件”**卡片和**“终端核对”**模块的 `RU`/`UA`/`EN` 本地化；在控制台中使用人类可读状态替代内部代码；并在工作室应用草稿时执行严格的参数对比。
4. **经纪商模式下的诊断 Demo 路由与验证边界（`stable` CI + FTMO MT5 Demo 验收测试机）：**

## 未来演进方向（规划中与延后项目）

2026 年 11 月 14 日作为主开发分支下一轮交付工作描述的策略目录、启动就绪面板与统一控制台，已包含在已发布的 `v0.15.0-alpha` 及后续版本中（见上文）。上一快照中列为“已在主分支中准备”的图形化控制台，已自 v0.19 起包含在发布版中（见上文）。后续方向（不预先承诺版本号、发布日期或实时验收）：

- **规划中 — 多交易执行器与投资组合管理：** 跨多个品种与交易时段对专业交易智能体进行投资组合级协调、资金分配、执行投资组合级自营公司风险规则、端到端回撤控制及市场状态分析。多个智能体的并行交易循环、按账户共享的风险控制以及每个账户的后台 MT5 实例自 v0.18 起已包含在发布版中（见上文）。
- **规划中 — 平台目录与专有 TradeLocker 接入：** 扩充自营公司与交易平台适配器的统一注册表；在当前版本中，**MetaTrader 5 (MT5)** 是当前启用的交易连接器，**FTMO** 是当前支持的自营公司接入，而 **TradeLocker** 接入已列为独立的计划里程碑。
- **规划中 — 已保存的交易智能体工作流：** 用于就绪检查、市场研究、合规自营规则执行以及计划性风险控制的自动化多步可复用流程。
- **设计阶段 — 许可与访问层级体系：** 访问密钥与封闭公测模式（`Free` / `Pro` / `Tester`）的架构设计、设备绑定以及功能层级划分，且不与交易执行权限相混淆（具体方案、价格及商业销售条款尚未敲定）。
- **已延后（不阻碍当前开发路径）：** 带有用于手动编程的独立内置代码编辑器与支持数据集管理的自定义深度历史回测引擎的增强版工作室，以及购买付费 Windows **Authenticode** 发布者证书和独立自定义域名（延后至产品实现盈利之后）。
