# Golden Breeze: Capabilities & Roadmap

**Language / Язык:** **English** · [Русский (docs/roadmap.md)](../roadmap.md)

**Status as of October 28, 2026** (available `v0.12.0-alpha` release in the `stable` channel verified on 28.10.2026). Golden Breeze is built as a multi-agent trading platform: collaborative work of specialized AI agents across the trading workflow — from market analysis and trading decisions to execution, position management, and risk control under user governance. Research, strategy development, versioning, and isolated strategy verification serve as a built-in engineering workflow of the platform, providing a transparent path from hypothesis to controlled execution.

## How to Read Statuses

- **In Release (`v0.12.0-alpha`, `stable`)** — capability is included in the published `FirstInstall` installer (`v0.12.0-alpha`) and verified by unit/integration tests; end-to-end live user acceptance may continue separately.
- **Verified** — a specific scenario has passed on the designated build with recorded evidence.
- **Implemented After `v0.12.0-alpha` / In Acceptance (`0.13–0.14-alpha`)** — capabilities integrated into the main development branch after `v0.12.0-alpha` and undergoing staged live functional acceptance on a dedicated rig ahead of the next public release.
- **Planned / Design Stage** — target roadmap tracks and architectural modules currently in the design phase.
- **Deferred** — standalone future capability or expense intentionally set aside so it does not block the current path.

> **Important Boundary:** publishing the `FirstInstall` installer, passing automated CI, and verifying auto-update confirm build delivery, but **do not imply completion of full functional acceptance** across all trading and UI scenarios.

## Implemented After v0.12.0-alpha & Currently in Acceptance (0.13–0.14-alpha cycle, snapshot as of October 28, 2026)

1. **Research & Strategy Engineering Tools in Chat (`0.13–0.14-alpha`):**
   - Multimodal chat attachments (images, `PDF`/`DOCX`/text/tables, extraction of up to 6 frames from video clips in an isolated process), built-in **Knowledge Library** with search and page citations, live **web search**, and a **child researcher subagent** (implemented with access restricted to the library and web without trading account access; live rig verification of researcher delegation is still pending), plus full support in the main chat for both **Claude CLI** and **Codex CLI (ChatGPT sign-in)**.
   - Python strategy code generation in chat, automated whitelist validation and synthetic-bar execution in an isolated process, strategy card with code preview, and registration into the Studio catalog via the **"Add to catalog"** button.
2. **Control Desk, Broker Timezones, FTMO & MT5 Terminal Enhancements (`0.13–0.14-alpha`):**
   - Closed-market bar history analysis without waiting for a live tick, history persistence across session breaks, FTMO trading session schedule, and weekly bar dating by server timezone (including DST transitions) protecting the trading pipeline from bars without verified UTC.
   - Auto-synchronization of the trading symbol in MT5 "Market Watch", background verification of broker server time, "Connect now" toggle and automatic adapter selection by platform family, non-activating window placement and termination of the dedicated MT5 terminal upon application exit, and `RU`/`UA`/`EN` localization of the "FTMO Conditions" card and "Terminal Reconciliation" block.
3. **Diagnostic Demo Route in Broker Mode & Live Rig Acceptance Progress (`111` checks):**
   - For the diagnostic verification path (manually enabling execution in Diagnostics, diagnostic run, and acceptance `BUY`/`SELL` trades), support was implemented for Studio agents in broker mode with fresh dual verification of demo account status from the MT5 terminal upon activation and before every order (this diagnostic route operates strictly on demo accounts and blocks real accounts, without changing general `Demo` and `Real` support in the platform).
   - The end-to-end acceptance run of `111` checks on the dedicated rig **is not yet complete** (the last recorded run on the previous rig candidate finished with incomplete status: **84 passed**, **4 failed**, **10 not run**, **6 requiring manual Figma layout review**, **7 pending external checks**). To close the manual execution enablement and verification order cycle steps (`XAUUSD` / `BTCUSD`, placing and modifying protective stops, mandatory `trailing-stop`, and verifying zero residual positions at the broker) that remained open on the previous candidate, fixes have been merged into the main branch for the next rig candidate.

## Planned Tracks & Design Stage

- **Multiple Trading Executors & Portfolio Management (Planned).** Scaling multi-agent trading: parallel coordination of specialized trading agents across multiple instruments and sessions, capital allocation, enforcement of verified prop-firm risk rules, end-to-end portfolio drawdown control, and market regime analytics.
- **Platform Catalog Expansion & Dedicated TradeLocker Integration (Planned).** Expanding the unified registry of connected trading platforms and prop firms with transparent capability cards for each adapter. **TradeLocker** connector integration is scheduled as a standalone planned task and does not block current MT5 acceptance.
- **Saved Trading Agent Workflows & Deep Validation (Planned).** Repeatable multi-step routines for readiness checks, market study, enforcement of verified prop-firm rules, task delegation, and risk governance.
- **Licensing & Access Tiers (Design Stage).** Architectural design of access keys and closed beta testing modes (`Free` / `Pro` / `Tester`), device binding, and capability tier separation without mixing licensing with trading permissions (plans, pricing, and sales terms are not yet approved).

## Deferred Decisions

- **Expanded Studio & Deep Historical Backtesting (Deferred).** A standalone built-in code editor for manual programming in Studio and a custom historical backtesting engine with dataset management are deferred so as not to delay core trading and multi-agent workflows (baseline strategy code generation in chat and isolated synthetic-bar verification are already implemented in `0.13–0.14-alpha`).
- **Authenticode Certificate & Custom Domain (Deferred by Project Decision).** Purchasing a paid Windows Authenticode publisher certificate for `.exe` binaries and a dedicated custom domain is deferred until the product reaches profitability. Meanwhile, update delivery is protected over HTTPS (TLS) and by cryptographic manifest signatures (Ed25519), and downloaded installer integrity is verified via `SHA-256`.
