Trading Platform Architecture

Core Modules of the Golden Breeze Platform

A single Windows application unifies trading agent governance, account and risk rule connections, market study, position management, and strategy engineering tools.

Control Desk & Agent Studio

In Release v0.12

Command center for trading agents: assigning instruments, accounts, and risk boundaries in Studio, studying the market over closed broker bars, checking trading setup readiness, and starting or stopping sessions with a full decision and trade log.

Status: available in v0.12.0-alpha; the 0.13–0.14 cycle adds closed-market analysis on the FTMO schedule, weekly bar dating by verified server timezone, and MT5 symbol auto-sync (in acceptance).

Chat, Knowledge Library & Researcher

v0.12 + 0.13–0.14

Tasking environment for the main agent (via Claude CLI in v0.12, and also via Codex CLI / ChatGPT sign-in in the 0.13–0.14 cycle): multi-chat management, reasoning levels, multimodal attachments (images, PDF/DOCX, video frames), Knowledge Library with page citations, web search, and a child researcher subagent.

Status: multi-chat and model controls are in v0.12.0-alpha; Knowledge Library, attachments, web search, and GPT main chat are implemented in 0.13–0.14 and undergoing acceptance (live rig check of the child researcher is still pending).

Accounts, Risk Control & Execution (MT5)

In Progress / Acceptance

Core trading integration of the platform: connecting Demo and Real accounts via MetaTrader 5, prop-firm and account cards, reconciling FTMO portal objectives with the terminal, diagnostic demo test route for Studio agents, and protective stop management.

Status: MT5 is the active trading connector (Demo and Real). The end-to-end acceptance demo cycle with orders and trailing-stop on the rig is still in progress (acceptance not yet complete); live trading acceptance on Real accounts is not claimed.

Executable Logic & In-Chat Strategy Release

Implemented in 0.13 / Acceptance

Built-in workflow for trading logic: binding a strategy version to an agent profile ("Behavior Review", including +sourcefree), and in the 0.13–0.14 cycle — writing Python strategy code in chat, isolated verification on synthetic bars, and one-click registration into the Studio catalog.

Status: catalog and version assignment are in v0.12.0-alpha; in-chat code generation and isolated verification are implemented in 0.13–0.14 and undergoing acceptance (standalone code editor and deep backtester are deferred).

FirstInstall Package & Auto-Update

In Release v0.12

Standalone Windows x64 distribution and direct one-click HTTPS updates with Ed25519 manifest signature verification, safe child process termination, build revision stamp verification, and preservation of agent profiles, accounts, and history.

Status: clean FirstInstall setup and stable channel updates are verified; functional acceptance of trading scenarios is tracked separately.

Multiple Trading Executors & Portfolio

Planned

Scaling multi-agent trading: parallel coordination of multiple trading executor agents across instruments and sessions, capital allocation, end-to-end portfolio drawdown control, TradeLocker connector, and licensing architecture.

Status: builds upon current Control Desk profiles and the researcher subagent; portfolio coordination of trading executors, TradeLocker, and access tiers are planned milestones.

Here is how these modules work together during a real trading workflow:

Trading Workflow Logic

From Account Setup & Agent Tasks to Execution & Risk Governance

The user defines accounts, risk boundaries, and tasks from the Control Desk, while agents analyze the market, formulate decisions, and manage positions within granted permissions. In release v0.12, management operates across agent profiles with MT5; the 0.13–0.14 cycle adds the Knowledge Library, child researcher, and in-chat strategy code release, while multi-executor portfolio coordination advances in subsequent stages.

1

Trading Connection, Account & Risk

Connect a MetaTrader 5 terminal and account (Demo or Real) and optionally a prop-firm profile (FTMO) reconciling portal objectives with the terminal. Set maximum drawdown, risk per trade, and position limits that the agent is never allowed to exceed.

2

Agent Profile, Knowledge & Strategy

In Agent Studio and chat, configure the trading instrument (e.g., XAUUSD), timeframes, language core (Claude CLI in v0.12; also Codex CLI / ChatGPT in the 0.13–0.14 cycle), and strategy version. In 0.13–0.14, you can study Knowledge Library materials in chat, generate and verify strategy code in isolation, and register it into the Studio catalog.

3

Market Study & Readiness Check

Via "Study Market" and "Check Readiness", the agent evaluates closed bars (including closed-market analysis on the FTMO schedule and verified server timezone), while the Control Desk verifies MT5 terminal connectivity, symbol synchronization, and Algo Trading permission.

4

Trading Session & Execution

Once the user clicks "Start Trading", the agent acts within its assigned strategy and risk profile: formulating decisions, submitting orders, and enforcing mandatory protective stops via MT5.

5

Position Management & Control

Throughout the session, the agent manages open positions (including moving stops to breakeven and trailing-stop) and logs every decision in the Control Desk journal. The user monitors account state and can stop trading at any moment.

Windows x64 Distribution · Setup & Updates

Download Golden Breeze & Get Started

Initial installation is performed using the standalone FirstInstall package for Windows 10/11 x64. GitHub's auto-generated Source code (zip / tar.gz) archives contain only the files of this web showcase and are not the application installer.

1. Download & SHA-256 Checksum Verification

  • Download the FirstInstall package:
    GoldenBreeze-FirstInstall-0.12.0-alpha.exe (365.5 MiB) and the checksum file .sha256 .
  • Verify SHA-256 in PowerShell before launching (the hash confirms an exact byte-for-byte match between your downloaded file and the reference release artifact):
Windows PowerShell — SHA-256 check 
Get-FileHash .\GoldenBreeze-FirstInstall-0.12.0-alpha.exe -Algorithm SHA256
  • Reference SHA-256 for v0.12.0-alpha:
    d4546bc1fe718020f78315bbe98e4b232db044fb80bdb1061f1d2fe44ffd60a2
  • Windows SmartScreen prompt on first launch: the .exe file is not signed with a paid Windows Authenticode publisher certificate. Once SHA-256 matches, confirm launch manually: "More info" → "Run anyway" (see FAQ below for details).

2. First Launch, Accounts & Auto-Update

  • Bundled Runtime: the installer includes its own runtime environment and does not require installing Python, Node.js, or Git separately.
  • Connection Setup: select your interface language (RU / UA / EN), connect your AI provider in Settings, add a MetaTrader 5 trading account (Demo or Real), and configure risk boundaries. Never pass SSH keys, GitHub tokens, or developer secrets to the application.
  • Trading Workflow in the Control Desk:
    select agent profile and account → Study Market → Check Readiness → Start Trading → position management within risk limits → Stop.
  • One-Click Auto-Update (stable channel): after initial installation, updates are delivered directly from Golden Breeze's HTTPS update server (without GitHub). The application verifies the Ed25519 cryptographic manifest signature and notifies you: "A new version has been downloaded".
  • Data Preservation: clicking "Update now" runs a safe transition (Preparing → Updating → Launching), terminating child processes while preserving agent profiles, accounts, and chat history.

FAQ & Technical Reference

Answers on Platform Governance, File Verification & Updates

How are responsibilities divided between the user and AI agents in the trading workflow?
Golden Breeze is a multi-agent trading platform where the user sets operational boundaries and governs permissions from the Control Desk: selecting a connected trading account (Demo or Real), assigning an agent profile, a verified strategy version, and risk limits. Specialized agents analyze the market over closed bars, verify technical readiness of the trading setup, and—only after explicit session start—execute and manage positions (including protective stops and trailing-stop) within granted permissions. Every decision is recorded in the Control Desk log, and the user can stop the session at any moment. Installing or opening the application never starts trading automatically.
How do SHA-256 verification, Ed25519 manifest signatures, and Windows Authenticode certificates differ?
These three mechanisms serve distinct purposes:
1) Installer SHA-256 lets you verify that your downloaded GoldenBreeze-FirstInstall-0.12.0-alpha.exe binary matches the trusted release file byte for byte.
2) Ed25519 cryptographic signature (first-install.json.sig) and HTTPS (TLS) are used by the application itself to verify the authenticity of the update manifest and packages during automatic updates from the update server.
3) Windows Authenticode certificate is a paid publisher certificate for .exe binaries checked by Windows SmartScreen. The .exe binary is not currently signed with an Authenticode certificate (purchasing it is deferred until the project reaches profitability), so Windows requests manual confirmation on initial setup.
Why do download links point to the specific tag v0.12.0-alpha rather than /releases/latest?
Current Golden Breeze builds are published as pre-releases (alpha). On GitHub, the standard /releases/latest endpoint excludes pre-releases. Therefore, the showcase uses verified direct links to the v0.12.0-alpha tag and the full Releases list.
What is stored in this repository and where can I read detailed documentation?
The golden-breeze-releases repository is the official distribution showcase for the FirstInstall installer, release notes, and user guides (the core platform source code is developed in a separate private repository). Detailed materials are available directly in the repository: Installation & First Start (EN), Capabilities & Roadmap (EN), Showcase Maintenance Policy (RU), and GitHub Pages Publication Note (RU).
