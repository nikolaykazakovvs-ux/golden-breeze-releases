strategy cards show the actual number of passed checks and the exact version name. `v0.19` adds a graphical Control Desk: a live candle chart from the MT5 terminal with the applied strategy's lines, marks for strategy signals, AI core decisions and broker-confirmed trades, open-position lines, a "Strategy → Core → Broker" decision breakdown, and "Live Quote", "Market & Session Context", and "Event Feed" cards; There was no separate `v0.19.0` release for clients: after `0.18.1`, the next client release is `0.19.1`. No `v0.19` live acceptance report is published on the showcase; the install, update, and `FTMO-Demo` demo-trade checks of 12.11.2026 belong to the previous `v0.14.0-alpha` installer.

(For `alpha` pre-releases, use the direct tag link or the Releases page, because GitHub's `/releases/latest` URL excludes pre-releases.)
2. Download the standalone installer **[GoldenBreeze-FirstInstall-0.19.2-alpha.exe](https://github.com/nikolaykazakovvs-ux/golden-breeze-releases/releases/download/v0.19.2-alpha/GoldenBreeze-FirstInstall-0.19.2-alpha.exe)** (`407,597,200` bytes / `388.7 MiB`) and the checksum file **[GoldenBreeze-FirstInstall-0.19.2-alpha.exe.sha256](https://github.com/nikolaykazakovvs-ux/golden-breeze-releases/releases/download/v0.19.2-alpha/GoldenBreeze-FirstInstall-0.19.2-alpha.exe.sha256)**.
   - *Note:* `Source code (zip / tar.gz)` archives automatically generated by GitHub contain only the files of this showcase repository and are not the application installer.
3. Before running the installer, verify its `SHA-256` checksum in Windows PowerShell (this confirms an exact byte-for-byte match between your downloaded file and the trusted release artifact):

```powershell
Get-FileHash .\GoldenBreeze-FirstInstall-0.19.2-alpha.exe -Algorithm SHA256
```

Reference `SHA-256` value for `v0.19.2-alpha`:
`c7439901a73aadcfdd12bfe8fbc3795fbb77bca75a0f8b89acd75d9ee7603b7c`

4. **Executable Signature & Windows Defender SmartScreen:**
   - The `.exe` binary is not currently signed with a paid Windows **Authenticode** publisher certificate (purchasing it is deferred until the product reaches profitability).
   - As a result, Windows SmartScreen may display an unknown publisher warning on first launch. Once you have confirmed the `SHA-256` checksum matches, confirm launch manually: **"More info" → "Run anyway"**.
   - On Windows 11 systems with *Smart App Control* enforced, Windows does not provide a manual override for unsigned binaries — any decision to disable that OS mode rests solely with the user.

## 2. Preparing Your Workspace

- **Bundled Runtime:** the `FirstInstall` package includes its own runtime environment and does not require a separate installation of Python, Node.js, or Git.
- **Interface Language:** use the top bar to switch the interface language between **RU** (Russian), **UA** (Ukrainian), and **EN** (English). Your language selection persists across restarts and updates.
- **AI Providers & Trading Accounts:** in **Settings**, connect your chosen AI model provider (in `v0.19.2-alpha`, the main agent chat works on any connected and enabled core: **Claude CLI**, **Codex CLI / ChatGPT sign-in without an API key**, **Antigravity CLI**, **Kimi CLI**, the **OpenAI**, **Claude**, **Gemini**, and **OpenRouter** APIs, or a local **Ollama**; API keys are kept in the system credential store; the "Create API key" button only opens the provider's official key page, and "Refresh models" loads the current model list) and, when needed, configure a connection to your installed **MetaTrader 5 (MT5)** terminal (including the **"Connect now"** toggle, automatic adapter selection by platform family, and dedicated MT5 terminal auto-provisioning). Never pass SSH keys, GitHub tokens, or developer secrets into the application.
- **Account Type & Execution Permissions Check:** the platform supports connecting both `Demo` and `Real` MT5 accounts. When an account is connected, the application queries its type and parameters from the trading platform, and when signed in to a prop-firm portal (currently FTMO), links the prop-firm risk rules to the account. The special "demo-only" restriction applies exclusively to the diagnostic test route, whereas for working with a connected `Real` account the boundary is that live acceptance of `v0.14.0-alpha` was historically performed on `FTMO-Demo` (no report for `v0.19.2-alpha` is published on the showcase) and completed live trading acceptance on a `Real` account is not claimed.
- **Trading Workflow in the Control Desk:**
  **select agent profile and account → `One-shot market check (no trades)` → `Prepare launch` → `Start Trading` → position management within risk limits → `Stop`**.
  - Installing or launching the application never opens trades automatically; during an active session, the agent operates within the assigned strategy and risk limits under user supervision.
  - **Stop** ends new entries only: open positions keep their protection and `trailing-stop` until the broker confirms that none remain, and a Stop requested while the agent is starting is not lost; provider settings stay available meanwhile. Closing positions is a separate action. The **emergency core stop** is a separate block with two-step confirmation: it stops the core immediately, including `trailing-stop` monitoring, while stop-loss and take-profit already set at the broker remain; it does not close positions.
  - If a button is inactive (for example, the market is closed, there is no fresh broker tick, or *Algo Trading* is disabled in MT5), the Control Desk displays the specific reason and the step required to resolve it inside the action panel (in `v0.19.2-alpha`, the MT5 account configured in Settings is connected on demand when you prepare a launch or run a one-off market review; also active are immediate closed-bar analysis via **"One-shot market check (no trades)"** when the market is closed, background verification of broker server time, and automatic symbol addition to MT5 "Market Watch" while awaiting history synchronization are active).

## 3. One-Click Auto-Update (`stable` channel)

1. After initial installation via `FirstInstall`, subsequent `stable` channel updates are delivered directly from Golden Breeze's dedicated HTTPS update server (no GitHub access is required for updates).
2. The application verifies the cryptographic signature of the update manifest (**Ed25519**, `.sig` file) and package checksums. While the update downloads in the background, its progress is shown in the lower block of the left menu (a dot on the ⓘ button when the menu is collapsed) without a white overlay; when the package is ready, a compact reminder with **"Update"** and **"Later"** buttons appears in the lower left corner once per session. The update can also be managed from the **"About"** window.
3. A regular restart runs seamlessly, without intermediate service windows; a service window appears only for locked files, a long check, a rollback, or an error. If the agent core is active or an operation is in progress, the application waits for a safe completion point. If an external process is holding the application folder open, the update window displays the process name and resumes once the folder is released.
4. User agent profiles, connected accounts, and visible chat history are preserved. If an update fails, the application rolls back to the previous version and generates a short anonymized technical report (free of user-identifying paths, account numbers, keys, or database contents). If the application fails at startup or during an update, the service window offers a one-button anonymized diagnostic report (it is also available later in the **"About"** window) and returns a `#GB-XXXXXX` reference code to quote in your report; if there is no connection, the report is saved to a file. Personal paths, user names, keys, passwords, and account numbers are hidden automatically.
5. **Data compatibility since `v0.18.0-alpha`:** the update converts the application's local data to a new format. After it, versions `0.17.3-alpha` and earlier cannot open this data. To return to such a version, restore the backup made before the update via the recovery window; do not copy data between versions manually.
