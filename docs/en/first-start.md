## 1. Downloading & Verifying the FirstInstall Installer

1. Open [release v0.12.0-alpha in Releases](https://github.com/nikolaykazakovvs-ux/golden-breeze-releases/releases/tag/v0.12.0-alpha) and review the release notes. (For `alpha` pre-releases, use the direct tag link or the Releases page, because GitHub's `/releases/latest` URL excludes pre-releases.)
2. Download the standalone installer **[GoldenBreeze-FirstInstall-0.12.0-alpha.exe](https://github.com/nikolaykazakovvs-ux/golden-breeze-releases/releases/download/v0.12.0-alpha/GoldenBreeze-FirstInstall-0.12.0-alpha.exe)** (`383,300,782` bytes / `365.5 MiB`) and the checksum file **[GoldenBreeze-FirstInstall-0.12.0-alpha.exe.sha256](https://github.com/nikolaykazakovvs-ux/golden-breeze-releases/releases/download/v0.12.0-alpha/GoldenBreeze-FirstInstall-0.12.0-alpha.exe.sha256)**.
   - *Note:* `Source code (zip / tar.gz)` archives automatically generated by GitHub contain only the files of this showcase repository and are not the application installer.
3. Before running the installer, verify its `SHA-256` checksum in Windows PowerShell (this confirms an exact byte-for-byte match between your downloaded file and the trusted release artifact):

```powershell
Get-FileHash .\GoldenBreeze-FirstInstall-0.12.0-alpha.exe -Algorithm SHA256
```

Reference `SHA-256` value for `v0.12.0-alpha`:
`d4546bc1fe718020f78315bbe98e4b232db044fb80bdb1061f1d2fe44ffd60a2`

4. **Executable Signature & Windows Defender SmartScreen:**
   - The `.exe` binary is not currently signed with a paid Windows **Authenticode** publisher certificate (purchasing it is deferred until the product reaches profitability).
   - As a result, Windows SmartScreen may display an unknown publisher warning on first launch. Once you have confirmed the `SHA-256` checksum matches, confirm launch manually: **"More info" → "Run anyway"**.
   - On Windows 11 systems with *Smart App Control* enforced, Windows does not provide a manual override for unsigned binaries — any decision to disable that OS mode rests solely with the user.

## 2. Preparing Your Workspace

- **Bundled Runtime:** the `FirstInstall` package includes its own runtime environment and does not require a separate installation of Python, Node.js, or Git.
- **Interface Language:** use the top bar to switch the interface language between **RU** (Russian), **UA** (Ukrainian), and **EN** (English). Your language selection persists across restarts and updates.
- **AI Providers & Trading Accounts:** in **Settings**, connect your chosen AI model provider (in the published `v0.12.0-alpha` release, the main agent chat runs via Claude CLI, while Codex CLI / ChatGPT sign-in in Settings is already supported and becomes a full main chat engine in the `0.13–0.14-alpha` cycle) and, when needed, configure a connection to your installed **MetaTrader 5 (MT5)** terminal. Never pass SSH keys, GitHub tokens, or developer secrets into the application.
- **Account Type & Execution Permissions Check:** the platform supports both `Demo` and `Real` MT5 accounts. When an account is connected, the application queries its type and parameters from the trading platform, and when signed in to a prop-firm portal (currently FTMO), links the prop-firm risk rules to the account.
- **Trading Workflow in the Control Desk:**
  **select agent profile and account → `Study Market` → `Check Readiness` → `Start Trading` → position management within risk limits → `Stop`**.
  - Installing or launching the application never opens trades automatically; during an active session, the agent operates within the assigned strategy and risk limits under user supervision.
  - If a button is inactive (for example, the market is closed, there is no fresh broker tick, or *Algo Trading* is disabled in MT5), the Control Desk displays the specific reason and the step required to resolve it (the `0.13–0.14-alpha` cycle for the next release also adds background verification of broker server time and automatic symbol history synchronization in MT5 "Market Watch").

## 3. One-Click Auto-Update (`stable` channel)

1. After initial installation via `FirstInstall`, subsequent `stable` channel updates are delivered directly from Golden Breeze's dedicated HTTPS update server (no GitHub access is required for updates).
2. The application verifies the cryptographic signature of the update manifest (**Ed25519**, `.sig` file) and package checksums. When an update package is ready, a banner appears: *"A new version has been downloaded. The application will reopen automatically after updating."* with an **"Update now"** button.
3. The transition runs in three steps: **"Preparing → Updating → Launching"**. If the agent core is active or an operation is in progress, the application waits for a safe completion point. If an external process is holding the application folder open, the update window displays the process name and resumes once the folder is released.
4. User agent profiles, connected accounts, and visible chat history are preserved. If an update fails, the application rolls back to the previous version and generates a short anonymized technical report (free of user-identifying paths, account numbers, keys, or database contents).
