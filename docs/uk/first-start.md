**Стан на 22 листопада 2026 року** (доступний випуск у каналі `stable` опубліковано 22.11.2026; розмір, SHA-256 і підпис маніфесту первинного встановлення звірено 22.11.2026). Акт живого приймання `v0.17` на вітрині не опубліковано; перевірки встановлення, оновлення та демо-угод на `FTMO-Demo` від 12.11.2026 стосуються попереднього інсталятора `v0.14.0-alpha`.

## 1. Отримання та перевірка інсталятора FirstInstall

1. Відкрийте [випуск v0.17.3-alpha в розділі Releases](https://github.com/nikolaykazakovvs-ux/golden-breeze-releases/releases/tag/v0.17.3-alpha) та ознайомтеся з нотатками до випуску. (Для попередніх `alpha`-випусків використовуйте пряме посилання на тег або сторінку Releases, оскільки адреса `/releases/latest` у GitHub не включає `pre-release`.)
2. Завантажте автономний інсталятор **[GoldenBreeze-FirstInstall-0.17.3-alpha.exe](https://github.com/nikolaykazakovvs-ux/golden-breeze-releases/releases/download/v0.17.3-alpha/GoldenBreeze-FirstInstall-0.17.3-alpha.exe)** (`407 318 456` байт / `388,4 МіБ`) і файл контрольної суми **[GoldenBreeze-FirstInstall-0.17.3-alpha.exe.sha256](https://github.com/nikolaykazakovvs-ux/golden-breeze-releases/releases/download/v0.17.3-alpha/GoldenBreeze-FirstInstall-0.17.3-alpha.exe.sha256)**.
   - *Примітка:* архіви `Source code (zip / tar.gz)`, що автоматично створюються GitHub, містять лише файли інформаційної вітрини та не є інсталятором програми.
3. Перед запуском перевірте контрольну суму `SHA-256` у Windows PowerShell (вона підтверджує побайтовий збіг завантаженого файлу з довіреним артефактом випуску):

```powershell
Get-FileHash .\GoldenBreeze-FirstInstall-0.17.3-alpha.exe -Algorithm SHA256
```

Еталонне значення `SHA-256` для `v0.17.3-alpha`:
`3607b20aedbb28f66bec38657f32460c1a8ce44f03ca4182abce94813af613fa`

4. **Підпис виконуваного файлу та захисник Windows:**
   - Виконуваний файл `.exe` наразі не підписаний платним сертифікатом видавця Windows **Authenticode** (його купівлю відкладено до виходу продукту на прибуток).
   - Тому під час першого запуску інсталятора Windows SmartScreen може показати попередження про невідомого видавця. Якщо контрольна сума `SHA-256` збігається, підтвердьте запуск вручну: **«Докладніше» → «Виконати в будь-якому разі»**.
   - На системах Windows 11 з увімкненим режимом *Smart App Control* ручний обхід для непідписаних файлів системою не передбачено — рішення про вимкнення цього режиму користувач ухвалює самостійно.

## 2. Підготовка робочого простору

- **Вбудоване середовище:** інсталятор `FirstInstall` містить власний runtime і не потребує окремого встановлення Python, Node.js або Git.
- **Мова інтерфейсу:** у верхній панелі вікна доступний вибір мови — **RU** (російська), **UA** (українська) або **EN** (англійська). Обрана мова зберігається під час перезапуску й оновлення.
- **Провайдери ШІ та рахунки:** у розділі **Налаштування** підключіть обраного провайдера моделей ШІ (у випуску `v0.17.3-alpha` діалог головного агента працює на будь-якому підключеному й увімкненому ядрі: **Claude CLI**, **Codex CLI / вхід через ChatGPT без API-ключа**, **Antigravity CLI**, **Kimi CLI**, API **OpenAI**, **Claude**, **Gemini** і **OpenRouter** або локальна **Ollama**; ключі API зберігаються в системному сховищі; кнопка «Створити API-ключ» лише відкриває офіційну сторінку провайдера, а «Оновити моделі» отримує актуальний список моделей) і за потреби налаштуйте підключення до встановленого торгового термінала **MetaTrader 5 (MT5)** (доступний перемикач **«Підключити зараз»**, автовибір адаптера за сімейством платформи й автопідготовка виділеного термінала MT5). Не передавайте програмі SSH-ключі, токени GitHub або секрети розробника.
- **Перевірка типу рахунку та прав виконання:** платформа підтримує підключення як демо (`Demo`), так і реальних (`Real`) рахунків MT5. Під час підключення рахунку програма отримує його тип і параметри від торгової платформи, а під час входу до кабінету проп-компанії (у поточному контурі — FTMO) пов'язує правила ризику з рахунком. Спеціальне обмеження «лише демо-рахунок» діє виключно для діагностичного тестового маршруту, тоді як для роботи з підключеним `Real`-рахунком межа полягає в тому, що історично живе приймання `v0.14.0-alpha` проведено на `FTMO-Demo` (акт для `v0.17.3-alpha` на вітрині не опубліковано) і завершене живе торгове приймання на рахунку `Real` не заявляється.
- **Торговий цикл у Пульті керування:**
  **вибір профілю агента і рахунку → `Вивчити ринок` → `Перевірити готовність` → `Запустити торгівлю` → супровід позицій у межах лімітів ризику → `Зупинити`**.
  - Саме встановлення або запуск програми ніколи не відкриває угоди автоматично; під час активної сесії агент діє в межах призначеної стратегії та лімітів ризику під контролем користувача.
  - Якщо кнопка неактивна (наприклад, закритий ринок, немає свіжого тіка брокера або в терміналі MT5 вимкнено *Algo Trading*), Пульт указує конкретну причину та крок для її усунення всередині панелі дій (у `v0.17.3-alpha` рахунок MT5 з «Налаштувань» підключається на вимогу під час підготовки до запуску або разового розбору ринку; також працюють негайний аналіз закритих барів кнопкою **«Вивчити ринок»** при закритому ринку, фоновий прогрів перевірки годинника брокера й автоматичне додавання символу до «Огляду ринку» MT5 з очікуванням синхронізації історії).

## 3. Автооновлення за кнопкою (канал stable)

1. Після первинного встановлення `FirstInstall` подальші оновлення каналу `stable` доставляються напряму з власного захищеного HTTPS-сервера Golden Breeze (доступ до GitHub для оновлень не потрібен).
2. Програма перевіряє криптографічний підпис маніфесту оновлення (**Ed25519**, файл `.sig`) і контрольні суми пакетів. Поки оновлення завантажується у фоні, перебіг завантаження показано в нижньому блоці лівого меню (крапка на кнопці ⓘ у згорнутому меню) без білого оверлею; коли пакет готовий, один раз за сесію в лівому нижньому куті з'являється компактне нагадування з кнопками **«Оновити»** і **«Пізніше»**. Оновленням можна керувати й із вікна **«Про програму»**.
3. Штатний перезапуск відбувається безшовно, без проміжних службових вікон; службове вікно з'являється лише за зайнятих файлів, довгої перевірки, відкоту або помилки. Якщо активне робоче ядро агента або триває операція, програма чекає на безпечне завершення. Якщо теку програми утримує сторонній процес, вікно оновлення покаже його ім'я та продовжить встановлення після звільнення теки.
4. Користувацькі профілі, рахунки та видима історія діалогів зберігаються. У разі збою оновлення програма відновлює попередню версію та формує короткий знеособлений технічний звіт (без шляхів з ім'ям користувача, номерів рахунків, ключів і вмісту баз). Якщо застосунок не запустився або оновлення завершилося збоєм, службове вікно пропонує надіслати знеособлений діагностичний звіт однією кнопкою (пізніше це можна зробити й у вікні **«Про програму»**) і повертає код звернення `#GB-XXXXXX`, який варто вказати у зверненні; за відсутності зв'язку звіт зберігається у файл. Особисті шляхи, імена користувачів, ключі, паролі та номери рахунків приховуються автоматично.
